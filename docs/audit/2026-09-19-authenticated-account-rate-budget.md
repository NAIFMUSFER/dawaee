# حد الطلبات بعد المصادقة — 19 سبتمبر 2026

## النطاق والسبب

متابعة للبند **S8** بعد الرأس
`785a457a59ab4921cac0855f4f07e3f14e942662`. لا يتضمن هذا العمل migration
أو تغيير مزود أو نشر إنتاج أو بناء تطبيق أصلي أو حذف حسابات.

`@fastify/rate-limit` يعمل مبكراً في `onRequest` قبل المصادقة، ولذلك كان
`req.auth` غير موجود ومفتاح الحد العام هو عنوان الشبكة دائماً. إبقاء هذا
الترتيب ضروري: نقله لما بعد المصادقة يترك الرموز المزيفة والطلبات غير الموثقة
بلا حد. لكنه وحده يجعل عدة حسابات خلف NAT تشترك في حد واحد، ولا يضع سقفاً
لحساب موثّق يبدل عناوينه أو يعمل عبر أكثر من خادم.

قُرئت قبل التعديل سلسلة `server → authenticate → session → rate-budget →
app.consume_rate_budget` واختبارات العنوان الموثوق وتعدد النسخ والاحتفاظ.
دالة SQL الحالية تقبل scopes نصية عامة؛ لذلك لا يلزم تغيير مخطط.

## ما كُتب

- الحد المبكر بقي **300 طلب/دقيقة لكل عنوان** ويستمر بحماية كل ما يصل إلى
  الخادم، بما فيه التوكن غير الصالح. أزيل فرع `req.auth` غير القابل للوصول من
  مفتاحه حتى يطابق التعليق السلوك الفعلي.
- بعد نجاح توقيع JWT وفحص الجلسة الحية، يستهلك الحساب ميزانية PostgreSQL
  `api:account`: **240 طلباً خلال نافذة ثابتة مدتها 60 ثانية**. المفتاح HMAC
  مشتق من UUID الحساب ولا يخزن UUID أو عنواناً أو بريداً في الجدول. الميزانية
  مشتركة بين النسخ وتبقى عبر إعادة تشغيل API.
- فحص الجلسة والاستهلاك ينفذان في معاملة واحدة. نتيجة الرفض تُرمى **بعد
  COMMIT**؛ رمي 429 داخل المعاملة كان سيلغي الزيادة ويثبت العداد عند آخر طلب
  مسموح. الاستجابة تحمل `retryAfterSeconds`.
- بعض مسارات التوافق تقع تحت hook للمسار و`preHandler` معاً. أصبح
  `authenticate` idempotent داخل الطلب، فلا يعيد فحص الجلسة أو يحتسب الطلب
  مرتين بعد أن يثبت `req.auth` داخلياً. لا يمكن لرأس/جسم من العميل تعيينه.
- استنفاد الميزانية لا يمنع `logout` أو `logout-all` أو طلب حذف الحساب أو
  إزالة push لهذا الجهاز. هذه المسارات ما زالت تحتاج جلسة حية وتبقى تحت حد
  العنوان المبكر وحدود المسار الخاصة، حتى لا يحبس الحد مستخدماً داخل جلسة
  مشتبه بها.

## ما اختُبر محلياً

- **55 حالة ناجحة / 3 ملفات** في PostgreSQL/WASM، تشمل 94 migration بمالك
  NOSUPERUSER/NOBYPASSRLS. حالة HTTP حقيقية أثبتت 429 بعد السقف، بقاء الزيادة
  المرفوضة في الجدول، وجود إرشاد إعادة المحاولة، ثم نجاح logout ورفض الجلسة.
- نجحت إعادة فحص API TypeScript وESLint للمصدر والاختبارات و`git diff --check`.
- أضيفت أربع حالات PostgreSQL أصلية إلى `shared-rate-limit.test.ts` لا يمكن
  تشغيلها محلياً لعدم وجود PostgreSQL/Docker هنا: حساب واحد عبر خادمين وعنوانين
  يبقى في bucket واحد؛ حسابان خلف NAT يحصلان على مفتاحين؛ تجاوز الحد يستمر
  ويترك إنهاء الجلسة متاحاً؛ التوكن المزيف لا ينشئ bucket ومسار ذو hookين
  يُحتسب مرة واحدة. يلزم CI على الرأس المنشور قبل عدّها ناجحة.
- آخر أساس قبل هذه الحزمة، `785a457a`، اجتاز CI
