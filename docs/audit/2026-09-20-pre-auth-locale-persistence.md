# حفظ اللغة قبل التسجيل — 20 سبتمبر 2026

## العيب المثبت

شاشة اختيار اللغة تعمل قبل وجود حساب. كان `AppProvider` يغيّر اللغة والاتجاه
في الذاكرة، ثم يتوقف عمداً عن إرسال تفضيلات إلى `/v1/me/preferences` لعدم وجود
جلسة. التعليق في المصدر وصف الاختيار بأنه «محفوظ محلياً»، لكن لم توجد كتابة
دائمة للاختيار. بعد قتل التطبيق وفتحه كان يبدأ من لغة الجهاز، لا من آخر اختيار
صريح للمستخدم.

هذا منفصل عن عيب عكس اتجاه RTL الموثق سابقاً: أعلام الاتجاه الأصلية كانت تحفظ
الاتجاه، أما قيمة اللغة نفسها فلم تكن تُستعاد قبل التسجيل.

## الإصلاح المحدود

- أضيف مفتاح `dawaee.localePreference` في AsyncStorage لقيمة `ar` أو `en` فقط.
- المفتاح غير مرتبط بحساب ولا يحتوي هوية أو اعتماداً أو بيانات صحية؛ أضيف إلى
  قائمة جرد التخزين الصريح كي يفشل CI إذا ظهر مفتاح نصي جديد غير مراجع.
- كتابات اللغة المتسارعة متسلسلة، فلا تستطيع كتابة أقدم أن تنتهي بعد الأحدث.
- التهيئة دون جلسة تقرأ الاختيار قبل إظهار شاشات الدخول/التسجيل وتطبّق اتجاهه.
- تغيير اللغة دون جلسة ينتظر حفظ الاختيار قبل اكتمال الإجراء، ولا يجري طلب API.
- عند وجود جلسة يبقى صف تفضيلات الخادم والمخزن المشفر الخاص بالحساب هما مصدر
  بقية التفضيلات. لم يتحول أي سجل صحي أو رمز دخول إلى التخزين النصي.

## التحقق

- اختبارات التخزين: قبول العربية والإنجليزية، رفض القيمة التالفة، فشل التخزين
  الآمن، وترتيب اختيارين متسارعين.
- اختبار تهيئة كامل لـ`AppProvider`: جهاز عربي بلا جلسة واختيار إنجليزي محفوظ
  يعرض الإنجليزية ويطبّق اتجاهها بلا طلب API أو قراءة cache حساب.
- حزمة الهاتف الكاملة نجحت محلياً: **1,080 اختباراً / 156 ملفاً**، ومنها سباقات
  التفضيلات والجلسات والتهيئة التي تستعمل المزود الحقيقي.
- TypeScript للهاتف وESLint للملفات المتغيرة نجحا محلياً.

نجاح CI الكامل المطابق للمشروع يُسجل بعد تشغيله، ولا تعني حزمة الهاتف المحلية
أن إعادة التشغيل الأصلية الآمنة أو تجربة iPhone أُغلقت.

## المتبقي

الإصلاح يجعل اللغة المختارة والاتجاه المحفوظ متوافقين بعد تشغيل جديد، لكنه لا
يعيد تشغيل التطبيق تلقائياً فور قلب RTL/LTR. إضافة إعادة تحميل أصلية تحتاج
تسوية الكتابات والجلسة والطابور ثم تجربة جهاز حتى لا تفقد عملية جرعة أو تسجيل.
