## العقد والحدود

`POST /v1/auth/password/recover`، دون جلسة TADAWEE، يحتاج `{ idToken, newPassword }` فقط. الاستجابة الناجحة `{ updated: true }`؛ لا يصدر جلسة. أخطاء الإثبات القديم/المستخدم أو الحساب المفقود/المعطل عامة؛ فشل المزود503 وحد الطلبات429. حدود موزعة عبر PostgreSQL:30 محاولة/IP و10/رقم مثبت كل10 دقائق. SMS يرسله Firebase بعد فعل المستخدم وموافقته؛ لا يعاد تشغيل مسار OTP القديم المعطل ولا تُرسل رسالة من الاختبارات.

الواجهة تدعم الأرقام العربية/الفارسية/الإنجليزية، الرموز ذات6 أرقام، التحقق التلقائي فيAndroid، مهلة إعادة إرسال60 ثانية، الإلغاء وإبطال الاستجابات المتأخرة، ومنع النقر المكرر. الإثبات في الذاكرة فقط ويُحذف عند الخروج. إذا انقطعت الشبكة بعد الحفظ تُعاد النية نفسها خلال صلاحية الإثبات؛ بعد انتهائه يمكن محاولة الدخول بالكلمة الجديدة أو طلب رمز آخر. كلمة تغيّرت لاحقًا لا تُستبدل بإثبات سابق.

**قناة الاستعادة المتاحة في الكود: رقم الجوال المسجل عبر نسخة Android المسجلة في Firebase (`app.dawaee.mobile`).** حساب بريد فقط لا يملك قناة استعادة بريدية مهيأة؛ يعرض ذلك بوضوح. Web/iOS وحزمة audit المنفصلة لا تدّعي إرسال SMS: تحتاج تسجيل تطبيق Firebase وإعداد قناة معتمدة. هذه حدود BLOCKED، وليست PASS شاملًا لكل الحسابات. لا يُدعى نجاح SMS الفعلي أو صلاحية Firebase/الفوترة/Play Integrity بمجرد نجاح CI.

استخدمت اختبارات الشاشة محاكاة حدود React/I/O، واختبارات التوقيع jose فعلية مع مفتاح وشهادات اختبار. اختبارات قاعدة البيانات تستعمل PostgreSQL الحقيقي في CI وmock لمزود إثبات الجوال فقط؛ لا mocks للـSQL أو المعاملة. 17 اختبارًا محليًا/3 ملفات PASS تشمل الشاشة والتحقق المجاور. TypeScript للخادم والعامل والهاتف فُحص، ونتائج آخرcommit الكاملة في PR30.
